# Lighthouse и загрузка публичного сайта — 4 ноября 2026

## Методика

Проверяется production-сборка (`npm run build`), а не сервер разработки.
Lighthouse 13.1.0, отдельный Headless Chrome 156. Исходный замер и изолированный
вариант выполнены через Vite Preview `http://127.0.0.1:8004/`; итоговая проверка —
через полный локальный сервер `http://127.0.0.1:8005/` с отдельной тестовой БД,
настоящим API и включённым gzip.
Мобильный профиль: 412 × 823, замедление CPU ×4, моделируемая мобильная сеть.
Категории: Performance, Accessibility, Best Practices, SEO. Перед каждым прогоном
Lighthouse сбрасывает хранилища своего отдельного профиля браузера.

Показатели относятся к лабораторной локальной проверке: они не заменяют замер
развёрнутого сайта с реальными заголовками, CDN и полевыми Core Web Vitals.
Автоматический балл доступности также не заменяет ручную проверку клавиатуры и
экранного диктора.

## Изолированная оптимизация загрузки

Исходная публичная страница загружала весь кабинет, включая его стили, даже при
посещении `/`. `React.lazy` разделяет загрузку по маршруту: кабинет запрашивается
только на `/app…`; параметры входа и приглашения остаются в адресе без изменений.

| Вариант | Performance | Accessibility | Best Practices | SEO | Передано | FCP | LCP |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Исходная сборка | 93 | 91 | 100 | 100 | 253 КиБ | 2,4 с | 2,6 с |
| Только отложенная загрузка кабинета | 98 | 91 | 100 | 100 | 141 КиБ | 1,8 с | 1,8 с |
| Повтор этого же варианта | 98 | 91 | 100 | 100 | 141 КиБ | 1,8 с | 1,8 с |

Исходный JavaScript: 580,37 КБ до gzip; после разделения: 231,50 КБ публичной
части и 349,20 КБ кабинета. CSS: 178,08 КБ → 49,59 КБ публичной части + 128,49 КБ
кабинета. В сетевом журнале публичной страницы нет запросов файлов `Workspace`.
В обоих прогонах Total Blocking Time равен 0 мс, ошибок консоли нет.

Исходная страница имела реальные проблемы доступности: низкий контраст текста,
кнопка управления просмотром внутри `tablist` и несовпадение видимого текста
этой кнопки с её доступным именем.

| Главная, настольный | 100 | 100 | 100 | 100 | 0,4 с | 0,4 с | 0 |

Новая главная передаёт 145 КиБ вместо исходных 253 КиБ: на 43% меньше.
Публичный JavaScript — около 270 КБ, CSS — около 25 КБ до gzip. Стили общих контролов
и рабочего кабинета загружаются вместе с кабинетом, без запросов на главной.
Во всех четырёх итоговых прогонах TBT — 0 мс; ошибок в консоли и провалов проверки
контраста нет. На первой проверке новой главной обнаружен пропущенный уровень
заголовка перед демонстрацией процесса; добавлен доступный заголовок раздела и
проверка повторена до Accessibility 100.

На полном сервере обнаружены ещё две причины ухудшения загрузки: отсутствие
сжатия статических файлов и скачок футера после проверки входа на `/start`.
После gzip и стабильного каркаса формы её балл вырос с 71 до 99, CLS снизился
с 0,429 до 0,025, передача — с 328 до 130 КиБ.

Предварительная загрузка локальных Cyrillic и Latin шрифтов убрала сдвиг
демонстрации процесса на главной: CLS 0,098 → 0, Performance 96 → 99.
Эффект подтверждён повторным прогоном: `font-preload-mobile` и
`final-verified-mobile` дали одинаковые баллы и CLS 0. Vite заменяет ссылки на
хешированные имена; оба адреса проверены: HTTP 200, `font/woff2`. Отдельно
проверен режим разработки: небольшой плагин Vite корректно направляет ссылки
к зависимостям вне корня `web/`. Внешних запросов шрифтов нет.

По скриншотам самих отчётов проверены мобильные главная, тарифы, форма начала работы и
настольный первый экран. Шрифт, иконки и переносы отображаются корректно.
Мобильная таблица тарифов имеет собственную горизонтальную прокрутку.

Итоговые отчёты: `final-verified-mobile.report.*`,
`final-verified-pricing-mobile.report.*`, `final-verified-start-mobile.report.*`,
`final-verified-desktop.report.*`. Остальные отчёты — промежуточные этапы проверки.

После итоговой полировки повторены мобильные проверки главной, тарифов, начала работы и страницы запросов по данным: **99 / 100 / 100 / 100** в каждой. Сдвиг формы — 0,025; на остальных страницах — 0. Артефакты: `final-release-{home,pricing,start,legal}-mobile.report.*`. Это локальные лабораторные проверки, не полевые данные работающего домена.

## Повторение проверки

Для полной проверки, включая форму начала работы, в первом терминале:

```sh
npm run build
mkdir -p var/lighthouse-nov4
DATABASE_PATH="$PWD/var/lighthouse-nov4/audit.sqlite3" DATABASE_URL= APP_ENV=test APP_URL=http://127.0.0.1:8005 SECURE_COOKIES=false .venv/bin/python -m uvicorn server.main:app --host 127.0.0.1 --port 8005
```

```sh
LIGHTHOUSE_OUTPUT_DIR=var/lighthouse-nov4 node scripts/lighthouse.mjs http://127.0.0.1:8005/ final-mobile mobile
LIGHTHOUSE_OUTPUT_DIR=var/lighthouse-nov4 node scripts/lighthouse.mjs http://127.0.0.1:8005/pricing final-pricing-mobile mobile
LIGHTHOUSE_OUTPUT_DIR=var/lighthouse-nov4 node scripts/lighthouse.mjs 'http://127.0.0.1:8005/start?plan=trial' final-start-mobile mobile
LIGHTHOUSE_OUTPUT_DIR=var/lighthouse-nov4 node scripts/lighthouse.mjs http://127.0.0.1:8005/ final-desktop desktop
```

Скрипт запускает закреплённый `lighthouse@13.1.0` через официальный npm registry
и сохраняет HTML, полный JSON и краткую сводку JSON. Lighthouse не добавляется
в зависимости приложения. Для уже установленного Lighthouse можно задать
`LIGHTHOUSE_CLI=/absolute/path/to/lighthouse/cli/index.js`. `CHROME_PATH` позволяет
выбрать установленный Chrome, если он не обнаруживается автоматически.

Отчёты сохраняются в игнорируемом Git каталоге `var/lighthouse-nov4/`;
исходные прогоны: `baseline.report.*`, `lazy-workspace.report.*`.
