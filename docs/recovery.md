# Процесс взыскания

Код: `server/recovery_rules.py` (правила), `server/recovery.py` (API), `server/recovery_templates.py` (документы), `server/financing.py` (финансирование). Тесты: `tests/test_recovery.py`.

## Этапы

| Этап | Статусы |
| --- | --- |
| Досудебная работа | Новый → Напоминания → Претензия готова → Претензия отправлена → Можно передавать в суд. Отдельно: обещание, нарушенное обещание, спор |
| Суд | Выбор маршрута → Ожидает пошлины → Пошлина оплачена → Проверка юристом → Готово к подаче → Подано → Приказ или решение |
| Исполнение | Исполнительный документ → банк или ФССП → деньги. Если денег нет: намерение о банкротстве или списание |

Два перехода происходят без действий пользователя. Долг с нулевым остатком становится оплаченным, а по истечении срока ответа на претензию открывается суд.

## Что считает код

- Маршрут: приказ для бесспорного документального долга до 750 000 ₽, иначе иск.
- Госпошлина по ст. 333.21 НК РФ, проценты по ст. 395 ГК РФ.
- Готовность к суду: договор, документы об исполнении, доверенность, подтверждение отправки претензии.
- Сроки: исковая давность, ответ на претензию, возражения на приказ, предъявление листа.
- Порог банкротства: 2 000 000 ₽ для компании, 500 000 ₽ для ИП, нужен судебный акт в силе.

Передачу в суд, проверку юриста и банкротство подтверждает руководитель. Автоматизация никогда не отправляет дело в суд сама.

## Документы

Претензия и судебные заявления используют один текст фактов. Шаблоны редактируются в кабинете. Каждый документ проверяет человек; подписание и подача выполняются вне системы, результат вносится в карточку.

## Финансирование

Система оценивает должника по четырём продуктам из `server/financing_catalog.json`. Заявка уходит партнёру только с согласия клиента. Сейчас заявками управляет оператор:

```bash
python -m scripts.financing_requests list
```

Погашение партнёру считается по банковским поступлениям от должника после даты финансирования.
