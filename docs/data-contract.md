# Контракт данных первого выпуска

Дата: 24.10.2026. Этот документ описывает текущую реализацию. Расширенная схема в исследовании ML — план развития, не существующий API.

## Деньги, даты и организация

- API принимает и возвращает суммы **в целых копейках RUB**. `amount=123456` означает 1 234,56 ₽. Плавающая точка, строки, нулевая/отрицательная сумма и сумма свыше 1 000 000 000 000 000 копеек не принимаются. Мультивалютности нет.
- `issued_on`, `due_on`, `paid_on`, дата обещания — календарные даты `YYYY-MM-DD`. Срок не раньше даты счета. Фактический платеж — не в будущем и не раньше счета. Обещание — сегодня или позже. «Сегодня», aging и обещания рассчитываются в `APP_TIMEZONE` (по умолчанию `Europe/Moscow`); недействительный IANA-пояс блокирует запуск. Настройка задается всему экземпляру сервера, отдельных часовых поясов клиентов пока нет.
- Технические даты создания/событий — UTC ISO 8601. Не смешивать их с календарными договорными датами.
- Регистрация создает организацию (`tenant`) и пользователя. Объекты выбираются внутри организации текущей серверной сессии; клиентский `tenant_id` не является основанием доступа. Приглашения коллег, административные роли и управление несколькими пользователями одной компании пока не реализованы.

## Основные объекты

| Объект | Текущий контракт |
|---|---|
| Счет | `company`, `number`, `issued_on`, `due_on`, `amount` обязательны. `inn` — пусто, 10 или 12 цифр; `email` и `notes` необязательны |
| Правка контакта | `PATCH /api/invoices/{id}/contact` принимает только `{email, notes}`; новый email может быть пустым. Снимает согласование неотправленных писем и фиксирует событие. Отправленные письма сохраняют исторического адресата |
| Уникальность счета | Внутри организации комбинация **точное имя контрагента + номер**. Это ограничение MVP: одинаковые имена/изменения написания нужно сверять вручную; ИНН пока не служит ключом объединения |
| Остаток | `amount - paid_amount`. Оплата сверх остатка запрещена; накопление платежей транзакционное |
| Статус | В базе `open`, `disputed`, `paused`. Представление выводит `paid` при нулевом остатке и `promised` при обещании. Просрочка считается отдельно по сроку и положительному остатку |
| Платеж | Положительная `amount`, `paid_on`, обязательный `reference`. Одна запись относится к одному счету. Повтор `(tenant, invoice, reference)` с теми же значениями не удваивает оплату; с другими значениями дает конфликт |
| Обещание | Одна текущая дата на счет. Обещание не меняет денежный остаток. Частичные обещанные суммы/график пока отсутствуют |
| Письмо | Тема, тело, адресат, источник (`template`/`yandex`), остаток при подготовке и состояния `draft`, `approved`, `sent`, `failed`. Провайдер Yandex получает только общий тон, финансовые факты подставляются локально. Изменение текста/остатка снимает согласование; пауза/спор/полная оплата блокируют отправку |
| Журнал | События внутри счета и организации: создание, подготовка/правка/согласование/отправка, платеж, обещание, смена статуса |
| Настройки | Имя компании, имя отправителя, Reply-To, банковские реквизиты, ставка калькулятора и интервал писем. SMTP-секреты — только переменные окружения сервера |

Первый выпуск не хранит договоры/сканы, полную банковскую выписку, автоматическое распределение платежа между несколькими счетами, отмены и кредит-ноты, исторические версии сроков, полноценный аудит чтений или point-in-time признаки ML. Поэтому журнал приложения и текущий экспорт не являются полноценным бухгалтерским регистром или датасетом для честного ретроспективного обучения.

После смены email старое письмо сохраняет прежнего адресата: его нельзя снова согласовать или отправить на новый контакт. Нужно создать новый черновик и согласовать его. Изменение только примечания также снимает действующее согласование неотправленных писем. Денежные поля, даты и контрагент через endpoint контакта не изменяются; произвольные дополнительные поля отвергаются. Правка контакта допускается и у оплаченного счета, но не открывает возможность отправки по закрытому долгу.

## Импорт CSV

UTF-8, BOM допустим. Разделитель — `;` либо `,`, определяется по первой строке. Рекомендуется `;`, чтобы десятичная запятая не требовала кавычек. До 10 000 строк счетов, до 1 500 000 символов поля `content`; максимальный HTTP-запрос — 2 000 000 байт, включая JSON. Неизвестные столбцы игнорируются, повторяющиеся после нормализации заголовки запрещены.

| Поле | Поддерживаемые заголовки | Формат |
|---|---|---|
| Контрагент* | `контрагент`, `компания`, `company` | Непустое название, до 200 символов |
| Номер* | `номер`, `номер счета`, `номер счёта`, `number` | До 100 символов |
| Дата счета* | `дата`, `дата счета`, `дата счёта`, `issued_on` | `2026-10-01`, `01.10.2026`, `01/10/2026` |
| Срок* | `срок`, `срок оплаты`, `due_on` | Те же форматы |
| Сумма* | `сумма`, `amount` | **Рубли**, `1234.56` или `1 234,56`; до двух дробных знаков |
| ИНН | `инн`, `inn` | 10/12 цифр или пусто |
| Email | `email`, `e-mail` | Адрес или пусто |
| Примечание | `примечание`, `notes` | До 5000 символов |

`*` — обязательный столбец и значение.

```csv
контрагент;инн;email;номер;дата;срок;сумма;примечание
Синтетический контрагент;;finance@example.com;TEST-001;01.10.2026;15.10.2026;1234,56;Искусственная строка для проверки импорта
```

В примере нет реального клиента. Пустой email разрешает учет, но блокирует отправку письма. ИНН нельзя автоматически «восстанавливать» из названия.

`POST /api/invoices/import/preview` принимает JSON `{"content":"...CSV..."}` и возвращает распознанные строки, ошибки по строкам и число дублей. `POST /api/invoices/import` повторно проверяет CSV. Если есть хотя бы одна ошибка — **ни один счет не импортируется**. Валидные дубли пропускаются, возвращаются `imported` и `skipped`; существующие счета не обновляются импортом.

Начальные `paid_amount`, остаток и платежи через CSV не импортируются. Сначала загружать согласованный набор счетов и отдельно фиксировать подтвержденные оплаты. Поля `оплачено`, `остаток`, `статус` из CSV-экспорта не будут восстановлены повторным импортом.

## Экспорт и резервное копирование

`GET /api/export` возвращает CSV с BOM и `;`: контрагент, ИНН, email, номер, даты, сумма, оплачено, остаток, статус. Деньги — рубли для человека. Текстовые значения с признаками формул экранируются для таблиц. Это экспорт текущего реестра, **не полная резервная копия**: в нем нет пользователей, сессий, писем, журнала и записей отдельных платежей. Для восстановления нужен `scripts/backup.py`.

## API и доступ

Сессионная HttpOnly/SameSite cookie, CSRF-токен в `X-CSRF-Token` на изменяющих авторизованных запросах, проверка `Origin` против настроенного внешнего адреса (`APP_URL`, либо автоматического `RENDER_EXTERNAL_URL` на Render). Не передавать токены, пароли и CSV в URL. Swagger/OpenAPI доступны по `/api/docs` и `/api/openapi.json` в development; в production отключены. Неизвестный `/api/...` отвечает JSON 404, а не HTML сайта.

Перед первым импортом бухгалтер должен подтвердить сумму, срок, отсутствие оплат/зачетов и полномочия работы с контактами. Приложение не проверяет юридическую действительность требования и не знает о поступлении, пока его не внесли.
