# Эксплуатация Mandato

Актуальный контур: Yandex VM, постоянный PostgreSQL, HTTPS по статическому IP. SSH только с IP оператора; CI автоматический, deploy вручную. Langfuse на VM не запускается. [Приёмка и границы](report-mvp-acceptance.md), [точный рецепт](../infra/yandex/README.md), [бюджет](research/yandex-vm-budget.md).

## Запуск и конфигурация

Локально — `python -m scripts.run_local`, приватный проектный `.env`, SQLite `server/data/mandato.sqlite3` и sidecar `mandato.sqlite3.agent-checkpoints.sqlite3`. Не запускать несколько local процессов на одной базе. Старые идентификаторы/счета сохраняются миграцией v1/v2 → v3; конфликты идентичности блокируют контакт и требуют разбора.

На VM — `compose.production.yml`, app non-root/read-only rootfs, приватный PostgreSQL без host port, Nginx только 80/443. `/etc/agentpay/production.env` имеет права `0600`; DB password создаётся один раз и не ротируется поверх существующего тома. Не выводить compose config/env в общие логи. `DATABASE_URL` важнее `DATABASE_PATH`; секреты не включать в Git, image, archive или CI outputs.

Для публичного запуска: точный `APP_URL=https://IP`, `APP_ENV=production`, `SECURE_COOKIES=true`. Только доверенный proxy перезаписывает forwarded headers. Без HTTPS вход/данные не использовать. Bootstrap HTTP открывает только ACME challenge и отдаёт 503 для остальных запросов, пока сертификат не получен.

Yandex API key и полный model URI передаются только в приватное окружение app. До включения оплачиваемого агента указать UUID владельца/согласованного клиента в `YANDEX_AGENT_TENANT_IDS`; значение берётся из собственного `/api/agent/status` после входа. Empty/foreign allowlist блокирует paid request. Новые публичные аккаунты не должны получать общий ключ. SMTP отдельно требует `SMTP_HOST`, TLS/учётные данные, `SMTP_FROM` и `SMTP_TENANT_ID`; сначала сверить владение ящиком/доменом. Подключённого внешнего ящика пока нет.

## Ручной выпуск

1. Пройти локальные проверки и успешный `Verify` для полного commit SHA в исходном `main`.
2. Сверить host fingerprint по аутентифицированному YC serial output, затем сохранить host key в отдельный known_hosts. Одного keyscan недостаточно.
3. Выполнить `scripts/deploy_yandex_vm.sh` с IP, SHA, private operator key и проверенным known_hosts. Скрипт передаёт точный git archive, сверяет checksum/commit, блокирует параллельный deploy, собирает образ до остановки старого приложения.
4. При повторном deploy старый app останавливается с drain, затем создаётся проверенный backup PG. Неуспешная копия отменяет upgrade и возобновляет старый app. После миграции нет автоматического затирания базы/непроверенного downgrade.
5. Проверить health, доверенный TLS, UI, вход, финансовую операцию на выделенном синтетическом tenant, сохранность после restart и таймеры. Только после успешного health меняется `/opt/agentpay/current`.

`deploy-yandex.yml` — выключенный opt-in для будущего решения владельца. Сейчас не задавать `YANDEX_VM_DEPLOY_ENABLED=true` и не передавать SSH private key в GitHub. Сохранённый Render Blueprint не используется; Render deploy из CI удалён.

## Копии и восстановление

**PostgreSQL:** `infra/yandex/backup.sh` создаёт private custom-format pg_dump в `/var/backups/agentpay`, проверяет table of contents и ротирует локальные файлы (~14 дней). Ежедневный systemd timer; копия перед каждым upgrade. Dump содержит бизнес-данные и PG checkpoints. Защищать как клиентскую базу. `scripts/postgres_backup.py` также умеет backup/restore с official PG17 client; URL передаётся окружением, не argv.

Restore допускается только в отдельную пустую БД. Проверить новую схему/таблицы, вход, суммы/allocations, историю, документы и ожидающий review агента; затем осознанно переключать приложение. Проверка `pg_restore --list` не заменяет настоящее восстановление. Не удалять старый том/архив до сверки.

**SQLite:** `scripts/backup.py --help`, `scripts/restore.py --help` — согласованная копия основной БД и offline restore. Для состояния агента нужен также checkpoint sidecar: остановить приложение и скопировать оба файла с закрытыми правами либо использовать PostgreSQL dump. CSV export не является резервной копией.

**Вне VM:** одна полная закрытая копия проверенного выпуска по согласию владельца сохранена на его Mac в `var/deploy/private-backups` (0700/0600), SHA256 сверена. Автоматической доставки туда нет. Копия только на диске VM не защищает от утраты всего диска. Отдельный private Object Storage/другая независимая площадка, ротация и restore должны быть подключены до реального клиентского портфеля. [Инструкция](../infra/yandex/object-storage-backup.md). Bucket/upload пока не считаются настроенными. Для реальной эксплуатации измерить и утвердить RPO/RTO.

## Сертификат, ресурсы, расходы

Let's Encrypt IP certificate shortlived (~160 часов); `agentpay-cert-renew.timer` дважды в сутки запускает renewal + nginx check/reload. Проверить `certbot renew --dry-run` и журнал service. Продление должно работать без вмешательства чаще срока истечения. Самоподписанный TLS/отключение проверки доверия не являются заменой.

2 vCPU20%, 2 ГБ RAM, SSD30ГБ, IPv4 ≈1 905 ₽/31 день по зафиксированным тарифам, без модельных запросов/платного исходящего трафика. Swap2ГБ — резерв пика сборки, не дополнительная RAM. Контролировать память/диск/backup size, OOM, health, ошибки API и срок сертификата. Langfuse отдельно, только после нового sizing/бюджета. Новые GPU, managed DB, load balancer не создаются.

Остановка VM не прекращает оплату диска/зарезервированного IP. Для полного завершения расходов сначала сохранить нужные копии, затем удалить **только ресурсы Mandato**, отвязанный boot disk и address, проверив ownership. Не трогать существующую default VPC/security group и другие проекты.

## Операционные инциденты

- Неоднозначная SMTP-ошибка: сверить журнал почтового провайдера до повторной отправки; не отмечать письмо доставленным автоматически.
- «Оплатили» в ответе: проверить выписку, внести банковский источник и распределение; агент сам денег не создаёт.
- Расхождение ОСВ/плательщика: бухгалтер разбирает источник/дату/ИНН, контакт по спорному долгу приостанавливается. Не править оплачено обходом ledger.
- Ошибочный финансовый факт: reasoned correction/reversal, затем пересоздать устаревший документ/предложение. Возврат денег и исправление исходной ошибки — разные операции.
- Неизвестная схема/ошибка миграции: закрыть запись, сохранить состояние/backup, не повторять destructive restore. Проверить восстановление отдельно.
- Компрометация ключа: отозвать у провайдера, заменить private env, пересоздать app и проверить binding; не публиковать значение в логах/чате.

## До реальных клиентов

Реквизиты владельца отложены. Нужны договоры, основания обработки/контакта, сроки хранения/удаления, поддержка и процесс восстановления доступа; юрист/бухгалтер, полномочия, настоящие источники/доказательства; рабочий ящик; независимые копии. Один ответственный пользователь на организацию — текущая граница пилота. Рыночные интервью, оплаченные пилоты и результат взыскания не заменяются техническим green CI.
