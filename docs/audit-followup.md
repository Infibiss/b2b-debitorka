# Итог повторной проверки AgentPay

24.10.2026. Запрос владельца: бесплатное размещение, полная сверка с исходным PDF, Yandex `.env`, агентный стек и голосовые звонки.

## Подтверждённое состояние

Предыдущий технический выпуск был назван готовым MVP слишком широко. Проверены все 25 страниц исходного отчёта; [матрица из 50 требований](report-gap-audit.md) показывает частичную реализацию даже прямо указанного MVP на стр. 17–18. Работающий кабинет не заменяет учётную сверку, расчёт требований/пошлин, юридические шаблоны с проверкой, мандат и фактический операторско-юридический процесс до банковского поступления. Эти функции не появились от добавления новых тестов.

В этом аудите исправлены воспроизведённые дефекты:

- Старое письмо после смены реквизитов/отправителя больше нельзя согласовать, отправить или повторно активировать редактированием. Новый черновик получает текущие данные. Миграция v1→v2 сохраняет финансовую и отправленную историю; старые неотправленные письма требуют пересоздания.
- Подтверждённый приём SMTP DATA не отменяется ошибкой последующего QUIT. Повторное согласование/отправка блокируются. Таймаут до подтверждения остаётся неоднозначным исходом, требующим сверки.
- Импорт не игнорирует неизвестные колонки. Файлы с оплатами, остатками, валютой и неподдержанными заголовками отклоняются до записи; обычный поддержанный реестр импортируется. Полноценный opening-balance импорт и синхронизация всё ещё отсутствуют.
- Явный локальный запуск `python -m scripts.run_local` читает `.env` без shell execution. Импорт приложения/CI этого не делают. Хостовые переменные имеют приоритет. `scripts.check_llm` отличает конфигурацию, HTTP-ошибку, отклонённый результат и настоящий успешный ответ; секреты не выводятся.
- Два одновременных первых запуска пустой SQLite больше не повторяют миграцию колонки и не понижают версию схемы: весь переход 0→1→2 проходит под одним write lock. Установка WAL после commit повторяет только временную BUSY/LOCKED ошибку с ограничением времени. Воспроизведение исходного сбоя и параллельные старты проверены на временных файлах.

## Бесплатный Render

Разместить сайт бесплатно возможно. Текущий сервис хранит SQLite локально и отправляет SMTP: Render Free не даёт постоянный диск, теряет локальные файлы при restart/redeploy/spindown и блокирует исходящие SMTP 25/465/587. Free Postgres Render истекает через 30 дней. Поэтому текущий полноценный кабинет нельзя надёжно опубликовать на этом варианте без архитектурных изменений. [Официальные ограничения](https://render.com/docs/free).

Бесплатная внешняя БД и HTTPS-почта — отдельный возможный вариант пилота после миграции и проверки тарифных лимитов/размещения. В этом аудите такие сервисы не создавались; размещение остаётся локальным по последнему явному решению владельца.

## Следующий продуктовый объём

1. Сверенный финансовый контур: контрагент по юридической идентичности, начальные остатки, diff повторных выгрузок, корректировки/зачёты/возвраты, банковский платёж и распределения с общим ограничением суммы.
2. Требования явного MVP отчёта: детерминированные расчёты по договору/применимым правилам и юридические документы, проверяемые практикующим юристом; операторский маршрут и фактический гонорар.
3. Агент входящих ответов: классификация → доказательства в тексте → предложение обещания/спора/запроса документов → согласование → идемпотентное исполнение. Фраза «мы оплатили» не создаёт подтверждённый платёж. Нужны согласованный набор evals и измеренное время работы сотрудника.
4. LangGraph для длительного состояния/возобновления и контролируемых переходов; LangChain по необходимости для адаптеров; Langfuse для оценок/трасс с согласованным размещением и минимизацией данных. Это предложенная архитектура, библиотеки в продукт ещё не внедрены.
5. Голосовой эксперимент на Yandex Realtime после текстового контура: собственный тестовый разговор, затем телефония/SIP и разрешённый список адресатов. Роли/scopes существующего ключа для Realtime пока не проверены; исходящий номер и маршрут отдельны от LLM-ключа.

LangGraph и наличие голосового бота сами по себе не доказывают превосходство над конкурентами. Проверяемая гипотеза — меньше ручной работы от сверенного долга до подтверждённой оплаты в российских учётных сценариях. Тариф и экономический эффект ещё нужно подтвердить оплачиваемыми пилотами.
