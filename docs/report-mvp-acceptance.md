# Приёмка программного MVP по исходному отчёту

Следующее расширение — [Mandato: портфельный выпуск](mandato-release.md). Ниже сохранена приёмка предыдущего программного MVP; новые адаптеры, аудит, прогноз и правила переговоров описаны в следующем протоколе.

Дата: 24.10.2026. Основание: исходный PDF, стр. 17–18 (семь требований M1–M7), полный прежний [аудит](report-gap-audit.md), [план реализации](superpowers/plans/2026-10-24-report-mvp-completion.md). Это сверка реализованных сценариев, не утверждение, что учтён любой возможный договор/учёт/спор.

## Закрытые финансовые риски

| Сценарий | Поведение / свидетельство |
|---|---|
| Историческая оплата, повторный изменённый импорт | Валовая сумма/оплачено/остаток проверяются совместно; preview, явное подтверждение, версия исходного состояния. `test_csv_financial_columns.py`, `test_finance.py`. |
| Два одинаковых названия с разными ИНН | Разные контрагенты. Конфликт старых данных сохраняется и ставит контакт на паузу. `test_finance_migration.py`. |
| Платёж на несколько счетов, параллельный/повторный запрос | Один банковский источник, общий предел распределений, idempotency; конфликт чужого плательщика/аванса требует разбора. `test_finance.py`, реальные PG-тесты. |
| Ошибка разнесения / возврат денег | Разные временные правила: исправление отменяет ошибочный факт на его дату, возврат действует датой возврата и не освобождает деньги для повторного разнесения. История сохраняется. |
| Зачёт, возврат товара, увеличение требования | Дата/основание и журнал; закрытый счёт допускает обоснованное увеличение требования. Устаревшие согласования аннулируются. |
| Частичное обещание / рассрочка | Сумма и транши; оплаты/сторно меняют исполнение графика. Обещание части суммы не помечает всю задолженность обещанной. |
| Стоп-лист / истёкший мандат | Пауза на контрагенте распространяется на все счета; агент/письмо проверяют актуальные разрешения и частоту контактов. |
| Смена выбранного счёта / ошибка сети | Предыдущий ledger очищается, запоздалый ответ не меняет новый выбор; кнопки не проводят операцию по прежнему счёту. Браузерная регрессия. |

## Агент

Реальный `StateGraph` и постоянные checkpoint в SQLite/PostgreSQL. Входящий текст с явным временем получения; ограниченная схема Yandex; точные цитаты, деньги/даты/отрицания/неоднозначность; мандат и текущий финансовый snapshot; обязательная остановка на проверку; идемпотентное исполнение. Факт платежа никогда не подтверждается текстом LLM.

Проверены рестарт, повторное согласование, чужие tenant, stale proposal, provider failure, injection/quoted history, относительные даты и timezone, превышение лимита запросов, недоступный Langfuse. [Протоколы replay, Yandex и реальной трассы](evals/README.md). Это небольшая регрессионная выборка, а не оценка точности на клиентской переписке. Обученный ML-скоринг не заявляется.

## Что ещё требуется до реальной услуги

- Реквизиты владельца (владелец отложил), договор/поручение обработки, условия сервиса и поддержки; реальные документы юриста/полномочия. На сайте их нельзя подменять вымышленными сведениями.
- Юрист и бухгалтер, принявшие формы/правила и реальный портфель; реальные экспорты 1С, первичка, банковские выписки, основания контакта. Файловые синтетические тесты не доказывают совместимость с любым шаблоном 1С.
- Корпоративная почта и её tenant binding, проверка реальной доставки; ручное получение ответов до mailbox-коннектора. Голосовой бот, банк/суд/ЭДО API не подключены.
- Независимые регулярные копии вне VM, восстановление и процедура доступа/удаления/инцидента. Один сервер не обеспечивает HA.
- Командные роли, приглашения, восстановление пароля нужны до самостоятельной многопользовательской эксплуатации. Сейчас сопровождаемый пилот с одним ответственным аккаунтом.
- Интервью, оплаченные пилоты, фактическая собираемость/часы юриста/экономика. Ни CI, ни LangGraph не подтверждают рыночное преимущество или заявленный эффект. Стартовая цена сайта — коммерческая гипотеза.

## Размещение и доказательства выпуска

Выбрана Yandex VM с постоянным PostgreSQL и HTTPS по IP. Langfuse на VM выключен; SSH только с IP оператора, deploy вручную. Фактический статус VM/CI/публичных проверок фиксируется в [протоколе выпуска](release-verification.md), а не выводится из наличия конфигурации. Инструкции: [эксплуатация](operations.md), [инфраструктура](../infra/yandex/README.md).
